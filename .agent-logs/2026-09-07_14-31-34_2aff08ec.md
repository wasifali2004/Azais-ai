Installed and switched to **Node 24.20.0 LTS via nvm** (`nvm install 24.20.0 && nvm use 24.20.0`) — flagging this since it's a machine-wide runtime change, easily reversible with `nvm use 20.20.2`.
3. **npm 11 blocked Prisma's postinstall** (its script-allowlist security feature) — Prisma's engine binary wouldn't download silently. Ran `npm install-scripts approve prisma @prisma/engines` (recorded in root `package.json`'s new `allowScripts` field).
4. **Prisma 7 changed its config model**: `prisma init` no longer puts `url = env("DATABASE_URL")` in `schema.prisma` — it now generates a `prisma7.config.ts` with `defineConfig(...)`, requiring `dotenv`. Added `dotenv` as a devDependency; this is why `apps/api/prisma7.config.ts` exists alongside `schema.prisma`.
5. **`prisma init` also scaffolded unrelated AI-agent skill folders** (`.claude/skills/`, `.agents/`, `.windsurf/`, `skills-lock.json`) — deleted, out of scope for this task.
6. **`tsconfig.json`'s `baseUrl` is deprecated under TS6** and hard-errored Nest's watch compiler (`nest start --watch` compiled but never served). Removed the unused option.
7. **Build output landed at the wrong path**: `prisma7.config.ts` sitting at the project root (outside `src/`) widened TypeScript's implicit `rootDir`, so compiled output went to `dist/src/main.js` instead of `dist/main.js`. Fixed by setting `rootDir: "./src"` and excluding `generated/`, `prisma7.config.ts`, and `dist` from both tsconfigs.
8. **Real bug in my own stub code**: Resend's SDK throws synchronously in its constructor when no API key is given — with `.env.example`'s empty placeholder, this crashed the whole Nest app at boot. Fixed `EmailService` to construct the client lazily only when `RESEND_API_KEY` is actually set.
